# RP-бот для Telegram + админ-панель

Бот на aiogram 3 под одно конкретное ТЗ: RP-отношения на «каплях крови», брак по
расчёту, фарма красных монет, игры (кости/дуэль/монеточка/пианино) со ставками
и наказаниями, профиль «кто я», правила, фан-команды, и отдельная веб-панель
для старшей администрации (не обязательно Telegram Mini App — обычный сайт,
доступ к которому можно ограничить по IP).

## Структура проекта

```
bot/                    — сам бот (aiogram 3, long polling)
  config.py              настройки из .env
  db.py                  схема SQLite (общая с админ-панелью!)
  repo.py                вся работа с базой (async, aiosqlite)
  emojis.py               ID премиум-эмодзи из пака + helper для <tg-emoji>
  middlewares.py         "работать только в одном чате" + учёт активности
  moderation.py           ядро модерации (чат, репорты, игры, очередь из панели)
  main.py                 точка входа бота
  handlers/
    profile.py            "кто я", "+описание"
    rules.py               "правила" + автопостинг после правки в панели
    farm.py                "фарма"/"ферма", "баланс"
    fun.py                 "кто …", "шанс …", "кто админ", /help, /links
    relationships.py       мутки/брак/расторжение, списки, команды отношений из панели
    modcmds.py             варн/мут/бан/кик и т.д. в чате
    reports.py             репорты с кнопками для модераторов
    rpfree.py              свободные RP-команды (ударить, обнять …)
    games/                 кости, дуэль, монеточка, пианино
admin_panel/             — веб-панель на FastAPI (отдельный процесс)
  app.py
  templates/  static/
data/                   — сюда по умолчанию кладётся bot.db (создаётся сама)
```

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:
- `BOT_TOKEN` — токен от @BotFather
- `ALLOWED_CHAT_ID` — id вашего чата (бот работает **только** в нём, при
  добавлении в любой другой чат сам пишет об этом и выходит)
- `BOT_USERNAME`, `BOT_CHANNEL_URL` — для команды `кто я` и `/links`
- `ADMIN_PANEL_SECRET` — код входа в панель
- `ADMIN_PANEL_ALLOWED_IPS` — через запятую, если хотите пускать панель только
  с конкретных IP (например, только со своего сервера/домашнего IP)

## Запуск

Одна команда поднимает **и бота, и админ-панель** (в одном процессе, общая база SQLite):

```bash
python -m bot.main
```

Панель откроется на `http://<ip сервера>:8080` (порт — `ADMIN_PANEL_PORT`, адрес —
`ADMIN_PANEL_HOST`) → ввести `ADMIN_PANEL_SECRET`. Отдельно запускать `uvicorn admin_panel.app:app`
**больше не нужно** — если он ещё работает, остановите его (`pm2 delete rp-admin`), иначе порт
будет занят: бот это переживёт (в логе будет ошибка), но панель с ботом не стартует.
Отключить панель: `ADMIN_PANEL_ENABLED=0`. Если панель не запустилась (порт занят и т.п.), бот
всё равно работает.

Через pm2 достаточно одного процесса:
```bash
pm2 start "python -m bot.main" --name rp-bot --cwd ~/rp-bot-tg/rp_bot --interpreter bash
pm2 save
```
(запускайте из окружения, где установлены зависимости, или укажите полный путь `.../venv/bin/python`).

В панели: искать пользователя по юзернейму/ID, выдавать варн/мут/бан, разбирать репорты,
редактировать правила (бот сам запостит их в чат), настраивать RP-команды и назначать админов.
Изменения из панели бот подхватывает сам (правила ~15 сек, модерация ~5 сек, RP-команды ~15 сек).

## Команды

**Профиль:** `кто я`, `+описание текст`
**Монеты:** `фарма`/`ферма` (раз в 4 ч), `баланс`
**Отношения:** `мутки`, `брак` (по расчёту), `расторжение`/`развод`, `мои отношения`, `отношения`, `браки`
**Игры:** `кости`, `дуэль`, `монеточка`, `пианино` (+ `ставка N`, иначе на наказание)
**RP без наград:** `ударить`, `обнять`, `поцеловать`, `погладить`, `пнуть`, `укусить`, `шлёпнуть`,
`пожать руку`, `дать пять`, `подмигнуть` — список и тексты правятся в панели
**Репорты:** `репорт причина` (ответом на сообщение нарушителя)
**Прочее:** `правила`, `варны`, `кто <вопрос>`, `шанс <событие>`, `/help`, `/links`
**Оформление:** `стараяверсия` — отвечать **вам** обычными сообщениями (без таблиц), `новаяверсия` — снова с таблицами
**Модераторам:** `варн [причина]`, `снять варн`, `мут [2ч|30м|1д|навсегда] [причина]`, `размут`,
`бан [причина]`, `разбан`, `кик`, `муты`, `баны`

Цель команды: ответом на сообщение, `@ник` (человек должен хоть раз писать в чат) или числовой ID.

### Кто модератор
Админы чата в Telegram **и** люди, которых назначили в панели (раздел «Администраторы»). Обычным
участникам команды модерации молча не отвечают. Нельзя наказать: бота, админов чата, назначенных
модераторов, самого себя. Если у бота нет прав — он честно пишет, что не получилось (а не «забанен»).
Бот должен быть **админом чата с правом ограничивать участников**.

### Репорты
`репорт причина` ответом на сообщение — бот публикует карточку (на кого, от кого, причина, текст сообщения,
ссылка на него) с кнопками **Варн · Мут 1ч · Бан · Удалить сообщение · Решено · Отклонить**. Кнопки доступны
только модераторам, репорт обрабатывается один раз. Раз в минуту с человека. Куда слать — `REPORTS_CHAT_ID`
(пусто = основной чат). В панели есть раздел «Репорты».

### Rich Messages (Bot API 10.1)
Telegram 11.06.2026 добавил `sendRichMessage`: HTML/Markdown с **нативными таблицами**, цитатами,
спойлерами, лимит 32 768 символов. Бот отправляет им списки (`браки`, `отношения`, `мои отношения`,
`муты`, `баны`, `варны`), `/help`, «кто я» (без аватарки) и правила. Метода нет в aiogram 3.15, поэтому он
реализован в `bot/rich.py` своим классом — библиотеку обновлять не нужно.

Лестница отката, чтобы сообщение не терялось: rich → обычный HTML (таблица превращается в строки
`ячейка │ ячейка`) → простой текст. Если сервер не знает метод (404), rich отключается на 10 минут.
`RICH_MESSAGES=0` выключает его полностью. Каждый человек может переключиться сам:
`стараяверсия` / `новаяверсия` (хранится в базе, переживает перезапуск; действует на ответы бота
этому человеку — это нужно тем, у кого старый клиент Telegram и таблицы не отображаются).
Правила из панели принимают Rich HTML, в том числе `<table bordered striped>`.

Не переведено на rich намеренно: сообщения игр, карточки репортов и модерации — они часто
редактируются, а правка rich-сообщений в этой версии не реализована; «кто я» с аватаркой остаётся
подписью к фото (в подписи таблиц нет).

### Оформление
Ники везде — кликабельные ссылки на профиль (`tg://user?id=…`), имена экранируются, так что ник вида `<b>`
ничего не ломает. «Таблички» — моноширинные блоки `<pre>` с выравниванием колонок (Telegram не умеет
настоящих таблиц); в них нельзя ссылки и премиум-эмодзи, поэтому списки пар/модерации сделаны цитатами
с кликабельными никами. Тексты правил из панели поддерживают HTML-разметку Telegram.

## Как настраиваются команды отношений (капли крови)

В разделе «RP-команды» панели можно добавить, например:
- триггер `свидание`, шаблон `{1} пригласил {2} на свидание`, +40 капель, кд 7200 сек
- триггер `привет`, шаблон `{1} поприветствовал {2}`, +5 капель, без кд

В чате команда используется ответом на сообщение партнёра: `свидание` (реплаем
на его сообщение). Капли крови растут только у **активных отношений**
(команда `мутки`), у брака по расчёту капель нет — он от них не зависит, как
и просили. Максимум — 1000 капель (настраивается в `bot/config.py`,
`Settings.max_blood_drops`). При падении до 0 отношения расторгаются
автоматически, как и при долгом неактиве (`RELATIONSHIP_INACTIVITY_DAYS`).

## Премиум-эмодзи

Пак ID вставлен в `bot/emojis.py`. В тексте сообщений используется официальный
тег Bot API `<tg-emoji emoji-id="...">fallback</tg-emoji>` — то есть реально
кастомные эмодзи, а не юникод. Ограничение, которое нельзя обойти на уровне
бота: **на inline-кнопках Telegram вообще не поддерживает форматирование или
custom emoji** — это ограничение самого Bot API, не библиотеки и не кода.
На кнопках стоят обычные юникод-эмодзи, максимально похожие по смыслу.

## Что стоит доделать под себя

Это рабочий, протестированный каркас (импорты, схема БД и вся админ-панель
прогнаны тестами — включая реальные HTTP-запросы через `TestClient`), но
несколько мест сознательно оставлены простыми, потому что в ТЗ по ним не было
точных цифр/деталей — поправьте под свой вкус:

- **Формулы шансов** в дуэли/монеточке/пианино (базовый шанс, бонус за стак
  прицела, прирост шанса за нажатие) — сейчас разумные дефолты в начале
  `duel.py` и `common.py`, легко подкрутить.
- **Автоматическое расторжение при неактиве** считается по активности участников: если хотя бы один из пары
  не писал в чат дольше `RELATIONSHIP_INACTIVITY_DAYS` дней, связь расторгается.
- **Список участников** для команды `кто <вопрос>` берётся из тех, кто уже
  писал в чат (Bot API не даёт списка всех участников группы) — это стандартное
  и единственно возможное для бота ограничение Telegram, не баг.
- **Telegram Mini App**: сейчас панель — обычный сайт с логином по секретному
  коду (как вы и предполагали — "можно даже не мини аппой"). Если всё же
  захотите встроить её как настоящий Mini App внутри Telegram, в
  `admin_panel/app.py` в функции `login()` оставлен комментарий, что нужно
  добавить (проверку `initData` вместо кода доступа).
- Наказание "мут на 1 час / варн на неделю" за проигрыш в дуэли без ставки —
  дефолт «мут на час» для игр без явного выбора наказания (кости/монеточка/
  пианино без ставки); в самой дуэли выбор наказания явный, как и просили.
